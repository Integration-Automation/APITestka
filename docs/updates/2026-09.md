## U-20260923-08 · 2026-09-23 · Action JSON is read and written as UTF-8; bad files raise · #bugfix #encoding

- **Found by**: ruff's B904 (raise without `from`) pointed at `utils/json/json_file/json_file.py`. The `except APITesterJsonException` clauses there could never fire, because nothing inside them raises that type.
- **Bugs**, all in `read_action_json` / `write_action_json`:
  - Files were opened with the locale encoding. On this machine that is cp950, so an action file saved as UTF-8 with characters outside cp950 (an emoji, many CJK characters) raised `UnicodeDecodeError`.
  - A missing file returned `None`. `execute_files` and `apitestka run <file>` then passed `None` to the executor.
  - Invalid JSON leaked a raw `JSONDecodeError`.
- **Fix**:
  - Both functions use UTF-8, and writes keep non-ASCII text as is (`ensure_ascii=False`) instead of escaping it.
  - A missing file, an unreadable one, invalid JSON or data that cannot be serialised raises `APITesterJsonException`, with the original error as its cause.
  - The lock is taken with `with`.
- **Callers**: the GUI's read, write and run handlers and the CLI already catch `Exception`, so they now show the message instead of acting on `None`.
- **Tests**: `test/test_utils/test_json_process.py` +5, all failing on the old code on this machine. Suite: 386 passed, 2 skipped.
- **Not changed**: the other B904 findings (`xml_file.py`, `json_process.py`, the request wrappers) have the same "catches its own exception type" shape. Look at them next.
