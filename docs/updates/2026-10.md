## U-20261001-04 · 2026-10-01 · Pact-style bidirectional contract testing · #done #contract

- **What** (`progress.md` #9): new package `je_api_testka/contract/`.
  - **Consumer contracts** (`pact.py`): records become Pact specification v2 files that a Pact Broker or Pactflow accepts as they are. Records with the same method, path, query and status make one interaction. The response body gets a `type` rule on `$.body` by default (`body_rule="equality"` for exact values), and `base_path` drops a prefix such as `/api/v1`. `add_interaction` writes interactions by hand with `providerState` and matching rules; `read_pact` validates a file.
  - **Matching** (`matching.py`): Pact v2 `type` / `regex` / `min` rules with cascading, most-specific-wins lookup and `[*]` / `.*` wildcards; objects may carry extra keys; headers compare case-insensitively and `Content-Type` by media type. `1` and `true` are not equal.
  - **Provider verification** (`verifier.py`): replays each interaction against a running provider through `requests` (with timeout, no redirects). Provider states are set through a callable or a setup URL that receives `{"consumer", "state"}`. A failed connection counts as a mismatch, and a contract with no interactions does not pass.
  - **Bidirectional check** (`openapi_compat.py`, `openapi_schema.py`): checks the contract against the provider's OpenAPI document without running the provider. The operation must exist: path templates match, the most literal template wins, and the first server URL's path is ignored. Query parameters must be declared, and required ones sent (path-level and `$ref` parameters count). Request and response bodies must fit their schemas, and the status must be declared exactly or as `2XX` / `default`. A dependency-free schema check covers local `$ref`, 3.1 type lists, 3.0 `nullable`, `enum`, `required`, `additionalProperties: false`, `items`, `allOf` / `anyOf` / `oneOf`.
  - **Entry points**: `apitestka contract record|verify|compare` (`cli/contract_cli.py`; exit 1 when the contract fails, 2 for unreadable files), `AT_write_contract`, `AT_verify_contract`, `AT_check_contract_against_openapi` (the last two raise `APIContractException` with the report). `APIContractException` joins the exception hierarchy.
- **Shared pieces**: `spec/path_templates.py` (template matching, server base path) for reuse by #13; `records_to_openapi.decode_body` is now public; `openapi_export.collect_records` feeds both OpenAPI export and contracts; `cli/cli_common.run_action_path` replaces the private `_run_path` in `cli_main.py`.
- **Tests**: new `test/test_contract/` (pact, matching, schema and compatibility, verifier against a Flask provider on a free port, commands, CLI and executor). It includes an end-to-end flow: the consumer run becomes a contract, the provider run becomes its OpenAPI document, the two are compatible, and the contract verifies against the live provider.

## U-20261001-07 · 2026-10-01 · Per-endpoint latency trends and anomaly detection · #done #trend #report

- **What** (`progress.md` #12): `utils/generate_report/latency_trends.py` adds `trend_endpoint_samples` to the trend SQLite file (the one `record_current_run` uses): one row per endpoint per run, with run id, label, time, sample count, and mean / p50 / p95 / max in ms. An endpoint is the method plus the OpenAPI template the path matches, or else the path with identifier segments generalized (`spec/path_templates.generalize_path`: numbers, UUIDs, 16+ hex characters → `{id}`, `{id2}`, ...).
- **Detection**: `detect_latency_anomalies` judges each endpoint of the latest run against the median and MAD of up to `window` (20) previous runs, once `min_history` (5) exist. The latest value is an anomaly when it is at least `min_increase` (20 %) and `min_delta_ms` (5 ms) above the median and the robust z-score `0.6745 * (x - median) / MAD` is above `threshold` (3.5); with no spread (MAD 0) the increase alone decides. Only slowdowns are flagged, and endpoints missing from the latest run are not judged. `assert_no_latency_anomalies` raises `APIAssertException` naming each anomaly.
- **Report**: `trend_report.generate_trend_report` writes an HTML table (latest value, baseline, z, runs, verdict) with an inline SVG sparkline per endpoint; endpoint names are HTML-escaped.
- **Entry points**: `apitestka trend record|check|report` (`cli/trend_cli.py`; `check` exits 1 on an anomaly), `AT_record_endpoint_latencies`, `AT_detect_latency_anomalies`, `AT_assert_no_latency_anomalies`, `AT_generate_trend_report`.
