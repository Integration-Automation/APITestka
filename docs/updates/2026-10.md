## U-20261001-01 · 2026-10-01 · records_to_openapi reachable from the CLI and MCP; merges responses · #done #openapi #cli #mcp

- **What** (`progress.md` #7): `apitestka openapi` infers an OpenAPI 3.1 document from saved JSON success reports (`--report`, repeatable), from action files it runs first (`--run`, repeatable), or both. It writes to `-o` or stdout and takes `--title` and `--api-version`. It exits with 2 when no source is given or a `--run` path is missing, and with 1 (writing nothing) when no successful record is found. The `apitestka_records_to_openapi` MCP tool takes `report_paths`, so a fresh MCP process can use an earlier run. New `spec/openapi_export.py`: `load_report_records` reads the `generate_json_report` success file (and turns its `"None"` / `b'...'` strings back into values), the MCP `{"successes": [...]}` dump, or a plain record list; `build_openapi` combines the in-memory record with those; `export_openapi` writes UTF-8 JSON and is registered as `AT_export_openapi`.
- **Fixes in `records_to_openapi`**: a response without a body used to get `content: {"application/json": {"text/plain": {}}}`, and it now has no `content`. Non-JSON text is `text/plain` with a string schema. A second record for the same operation used to replace the whole operation, and now each status code keeps its own response. Query parameter names become `in: query` parameters, and a JSON or text request body becomes `requestBody`.
- **Also**: `cli/completion.py` `SUBCOMMANDS` lacked `completion` and `mcp`; a test now compares it with the parser. Two older Sphinx warnings are fixed (MCP page title overline, an inline literal in `Zh_index.rst`), so `sphinx -W` builds cleanly.
- **Found, not fixed here**: `import`, `scaffold`, `curl_to_action`, `convert_har`, `generate_tests_from_openapi` and the `apitestka_test_api` MCP tool emit `AT_test_api_method_requests`, which the executor does not register. It is fixed in the next entry.
- **Tests**: `test/test_spec/test_records_to_openapi.py` (8 new, 2 of them regressions that fail on the old code), `test/test_spec/test_openapi_export.py` (new, including a round trip through `generate_json_report` against the local mock), `test/test_cli/test_cli_main.py` (5 new), `test/test_cli/test_completion.py` (parser parity), `test/test_mcp_server/test_tool_definitions.py` (3 new).
- **Result / numbers**: `pytest` 447 passed, 2 skipped (418 before); `sphinx -W` builds without warnings.
- **Files**: `je_api_testka/spec/{records_to_openapi,openapi_export,__init__}.py`, `je_api_testka/cli/{cli_main,completion}.py`, `je_api_testka/mcp_server/tool_definitions.py`, `je_api_testka/utils/executor/action_executor.py`; README ×3, `docs/source/{Eng,Zh}/doc/{cli,diff,mcp}`, `architecture.md` §2–§3.

## U-20261001-02 · 2026-10-01 · Imported, scaffolded and AI-generated actions run as they are · #bugfix #executor

- **What**: every converter produced actions the executor could not run. OpenAPI/Postman import (`apitestka import`), `curl_to_action`, `convert_har` and the deterministic `generate_tests_from_openapi` fallback returned `{"AT_test_api_method_requests": {...}}` dicts, which `execute_action` rejects (`KeyError(0)`). `scaffold` and the `apitestka_test_api` MCP tool used the list form, but that command name was never registered (`'NoneType' object is not callable`). All of them now go through the new `utils/executor/request_action.build_request_action`, which returns `["AT_test_api_method", {...}]` and sends a dict/list body as `json` and any other body as `data` (Postman raw text used to go out as `json`).
- **Executor**: `_execute_event` strips runner metadata (`id`, `depends_on`, `tags`) before the call, as only `run_actions_parallel` did. A tagged action used to reach `requests` as an unknown keyword. No registered command takes those names.
- **`assert_sla`**: `sla` may be a mapping (`{"max_ms": ..., "p95_ms": ...}`) and `records` defaults to the shared record's successes, so `["AT_assert_sla", {"sla": {...}}]` works from JSON. Before, JSON could only pass a dict, which failed on `sla.max_ms`, and `records` was required. The scaffold now emits that form instead of `"records": []`, which always passed.
- **Compatibility**: `curl_to_action` now returns a list and `convert_har`, `convert_openapi`, `convert_postman`, `convert_spec_file` return lists of lists. The old shapes were never runnable. No other workspace repo imports these functions.
- **Tests**: new `test/test_utils/test_generated_actions_run.py` runs each converter's output against the local mock and checks for success records and no errors; 3 new cases in `test/test_diff/test_sla_check.py`. Checked in a worktree of `4810743`: 11 of the new tests fail on the old code. The existing tests that pinned the dict shape now assert the list form.
- **Result / numbers**: `pytest` 460 passed, 2 skipped (447 before); `sphinx -W` clean.
- **Files**: `je_api_testka/utils/executor/{request_action,action_executor}.py`, `je_api_testka/{cli/import_specs,cli/scaffold_test,integrations/curl_import,integrations/har_import,ai/test_generator,mcp_server/tool_definitions,diff/sla_check}.py`; README ×3, `docs/source/{Eng,Zh}/doc/{integrations,diff,runner}`, `architecture.md` §3.

## U-20261001-03 · 2026-10-01 · Mock server serves WebSocket and gRPC endpoints · #done #mock #grpc #websocket

- **What** (`progress.md` #8): the mock server can now serve WebSocket and gRPC endpoints next to HTTP.
  - `utils/mock_server/websocket_mock.py`: `WebSocketMockServer` runs a `websockets` sync server in a daemon thread (port 0 picks a free port). Each `WebSocketRoute` can send a greeting, answer from a reply map (a string or a list of frames) and fall back to `{{message}}`, which echoes, or `None`, which stays silent. A `handler` callable can replace both. It keeps every received frame per path, and an unknown path gets HTTP 404 before the handshake.
  - `grpc_stub.py` (unary `bytes -> bytes` only before, and unreachable from JSON or the CLI): fixed unary responses, server streams, `add_error` with any gRPC status code, request capture, port 0, context manager. Payloads: `bytes` as-is (serialized protobuf), `str` as UTF-8, other JSON values as compact JSON. `configure_grpc_method` reads the JSON form (`response` / `response_base64` / `stream` / `error`).
  - `protocol_mocks.py` keeps one of each for JSON actions: `AT_mock_start_websocket_server`, `AT_mock_stop_websocket_server`, `AT_mock_websocket_received`, `AT_mock_start_grpc_server`, `AT_mock_stop_grpc_server`, `AT_mock_grpc_received`.
  - `mock_config.py` plus `apitestka mock --config FILE`: one JSON file with optional `http` (template routes, an `openapi` file relative to the config), `websocket` and `grpc` sections. The protocol mocks stop when the HTTP server exits.
- **Packaging**: new `grpc` extra (`grpcio>=1.60`) in `pyproject.toml` and `dev.toml`. `.github/requirements/ci.in` adds `websockets>=12.0` and `grpcio>=1.60`, and `ci.txt` is regenerated (only additions: grpcio 1.84.0, which has wheels for cp310–cp314 on Linux, macOS and Windows, and websockets 16.1.1 / 17.1), so CI runs these tests instead of skipping them. `uv.lock` adds grpcio.
- **Compatibility**: the WebSocket mock rejects unknown paths with `connection.protocol.reject`, because `ServerConnection.respond` does not exist in websockets 12.0, which the extra still allows. On 12.0 the handler failed and the client saw a 500, so the test now asserts the 404. Checked on Python 3.10 with websockets 12.0 and on 3.11 with 17.1. `GrpcStubServer` raises `MockServerException`, a subclass of the old `APITesterException`, when grpcio is missing.
- **Also**: `architecture.md` said `dev.toml` declares no scripts or extras; it has carried them since U-20260923-04. That line and the protocol-backend recipe are corrected.
- **Tests**: `test/test_mock_server/test_websocket_mock.py` (new; includes a round trip through APITestka's own `test_api_method_websocket`), `test_grpc_stub.py` (extended), `test_protocol_mocks.py` and `test_mock_config.py` (new, including `apitestka mock --config` with the blocking Flask run patched out).
