## Open

- **#3** [DECIDE] The PyPI classifier still says `Development Status :: 2 - Pre-Alpha`.
- **#6** GUI redesign: restructure and restyle. `gui/main_widget.py` is one 605-line widget (over the 500-line limit) with six flat tabs. It should become a sidebar-navigated window with a request/response split view, and history and environment panels docked (`gui/history_panel.py`, `gui/env_manager_model.py` exist but are not wired in). It needs a refreshed theme (`gui/main_window.py:21` hard-codes `dark_amber.xml`), pages for the newer features (#8–#13), and all four language wrappers (English, Traditional Chinese, Simplified Chinese, Japanese). `APITestkaWidget` stays the embeddable entry point (PyBreeze contract, `architecture.md` §6).
- **#7** `records_to_openapi` has no CLI subcommand (`cli/cli_main.py:101` `build_parser`). The MCP tool (`mcp_server/tool_definitions.py:74`) reads only the in-memory record, so a fresh MCP process gets an empty spec. Neither can read a saved JSON report or write a file. `spec/records_to_openapi.py:48` also labels a body-less response `application/json` → `text/plain`, and the last record per operation overwrites earlier status codes.
- **#8** Mock server: gRPC and WebSocket endpoints. `utils/mock_server/grpc_stub.py` serves unary calls only and is not reachable from `apitestka mock`, the executor or `flask_mock_server_instance`. There is no WebSocket mock endpoint.
- **#9** Pact-style bidirectional contract testing. `diff/contract_diff.py` only compares two OpenAPI documents. Missing: a consumer contract recorded from the consumer's tests (interactions plus matchers), provider verification replaying it against a running provider, and a cross-check of the consumer contract against the provider's OpenAPI.
- **#10** Reference AI backend on the Anthropic API. `ai/backend.py:1` ships only `NoOpAIBackend` and `StaticAIBackend`. Missing: an optional `ai` extra, an `AnthropicAIBackend` (key from the environment, never stored), and a way to select it (CLI, executor).
- **#11** Load-test bridge to LoadDensity. No way to turn APITestka actions into a LoadDensity run. It needs a converter to LoadDensity's action JSON (`LD_start_test` with `tasks`) and a runner that uses LoadDensity's `--execute_file` CLI. That is a new cross-project contract, so it also needs §6 in both repos and the root `AI_CONTEXT.md`.
- **#12** Response-time trends and anomaly detection. `utils/generate_report/trend_store.py:13` stores only run totals (success, failure, average elapsed). Missing: per-endpoint latency history, a baseline (median/MAD or EWMA), anomaly flags, and a trend report.
- **#13** Test-as-spec full loop. The pieces exist separately (`cli/import_specs.py` spec → actions, `spec/records_to_openapi.py` records → spec, `diff/contract_diff.py`, `spec/openapi_changelog.py`), but no single flow runs the tests, infers the spec, checks it against the committed spec, fails on drift, and generates actions for uncovered operations. Depends on #7.
